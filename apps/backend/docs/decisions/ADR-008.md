Autenticación basada en Access Token + Refresh Token (Cookie HttpOnly)

Decisión

CorreosClic utilizará desde la primera versión un esquema de autenticación compuesto por:

Access Token (JWT): se devolverá en el cuerpo de la respuesta.
Refresh Token (JWT): se almacenará en una Cookie HttpOnly.

Justificación
Mayor seguridad frente a ataques XSS.
El frontend nunca tendrá acceso al Refresh Token.
Compatible con las buenas prácticas modernas de autenticación.
Evita una futura migración de arquitectura cuando implementemos el refresco de sesión.

Consecuencias
SessionService se implementará desde UC-001.
El flujo de Login reutilizará exactamente la misma arquitectura.
